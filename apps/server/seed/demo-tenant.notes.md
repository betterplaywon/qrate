# 데모 테넌트 시드 — 검토 안내

`demo-tenant.json`은 **가상의 데모 고객사**다. README 페르소나 "희영"(2인 B2B SaaS 공동창업자)의 서비스를 가정해 만들었고, 실제 회사·수치가 아니다.

- 서비스: **마루인보이스** — 소규모 팀용 견적서·청구서 발행 SaaS
- 요금제: 무료(월 5건) / 스타터 월 9,900원 / 팀 월 29,000원(5명, 추가 1명당 5,000원), 연간 결제는 2개월 할인
- FAQ 26개, 5개 범주(요금·결제 6, 계정·팀 5, 기능 7, 데이터·보안 4, 지원 4)

## 검토할 때 볼 것

1. **사실의 일관성** — 같은 숫자(가격, 인원, 기간)가 항목마다 같은가. 모델은 자료를 그대로 믿으므로 자료끼리 충돌하면 답도 흔들린다.
2. **블록 단위** — `blocks`의 문단 하나가 인용의 최소 단위다. 한 블록에 서로 다른 사실을 너무 많이 넣으면 인용이 거칠어진다.
3. **말투** — 위젯 답변은 이 자료의 문장을 근거로 삼는다. 고객에게 보여도 되는 문장인지.
4. **이름** — `마루인보이스`, `status.maru-invoice.example`은 바꿔도 된다. `tenant.id`/`apiKey`(`demo`)는 위젯 기본값과 맞춰져 있어 바꾸면 `packages/widget/src/index.ts`도 같이 고친다.

## 의도적으로 비워 둔 주제 (W5 "문서에 없는 질문" 케이스용)

아래 질문은 실제 고객이 물을 법하지만 자료에 **일부러 넣지 않았다**. 모델은 모른다고 답하고 상담원 연결을 권해야 한다.

- 모바일 앱이 있는지
- 외화(달러·엔) 청구, 해외 고객 결제
- 공개 API나 웹훅 제공 여부
- 발행한 청구서를 국세청 전자세금계산서로 전송하는 기능 (자료에 있는 것은 "구독 요금"에 대한 세금계산서만)
- 카카오톡 알림
- 할인 쿠폰·프로모션 코드
- 특정 날짜의 장애 원인
- 계정 소유권 이전(양도)
- 경쟁 제품과의 비교

이 목록은 평가셋을 만들 때 "모른다 + 상담원 연결"의 정답지로 쓴다. 자료에 새 항목을 추가하면 이 목록도 함께 고친다.

## 실측 (2026-11-03, Sonnet 5.5, 사고 끔)

시스템 지시 + FAQ 26개를 search_result 블록으로 넣은 프롬프트 접두사는 **7,399 토큰**이었다(첫 요청의 `cacheCreationInputTokens`).
같은 대화의 두 번째 요청은 그 7,399 토큰이 전부 캐시에서 읽혔고(`cacheReadInputTokens`), 새로 계산한 입력은 265 토큰(이전 턴 + 새 질문)이었다.
두 요청의 TTFT는 1,418ms → 1,058ms. 2회 측정이라 경향만 참고하고 수치로 인용하지 않는다.
