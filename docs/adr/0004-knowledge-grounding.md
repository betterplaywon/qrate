# ADR-0004: 지식 연결 — 전량 주입 + API 자체 인용

- 상태: proposed → 본인이 결정 이유·트레이드오프를 채운 뒤 accepted로 변경할 것
- 날짜: 2026-11-02
- 작성: 강지원

## 맥락

모델은 고객사의 요금제·환불 규정·지원 시간을 모른다. 모르는 질문에도 그럴듯한 답을 지어낼 수 있고,
상담 위젯에서 틀린 정책 안내는 "모르겠다, 상담원에게 연결하겠다"보다 나쁘다.
그래서 답하기 전에 고객사 지식을 프롬프트에 넣어야 하며, 두 가지를 정해야 한다.

1. **무엇을 넣는가**: 지식 전부를 넣을지, 질문과 관련된 조각만 골라 넣을지.
2. **출처를 어떻게 보증하는가**: 답의 근거가 된 FAQ를 위젯에 어떻게 보여 줄지.

MVP 전제: 데모 고객사 1곳, FAQ 20~30개(README 페르소나 기준의 가상 B2B SaaS). 항목당 토큰 수는 실측 전이다.

## 고려한 대안

### 무엇을 넣는가

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| 전량 주입 + 프롬프트 캐싱 (선택) | 검색 단계가 없어 놓치는 FAQ가 없음(`selectKnowledge`가 전부를 같은 순서로), 검색 색인·임베딩 없이 메모리·Postgres 저장소 그대로, 접두사가 요청마다 같아 5분 안의 다음 질문은 캐시 읽기(데모 FAQ 답 1건 $0.0028, 2026-11-12 실측) | 요청마다 FAQ 전체가 입력이 됨(데모 3,740자 8,958토큰, 3만 자 38,390토큰·처음 읽기 $0.0925, 2026-11-12 실측), 캐시는 마지막 사용 뒤 5분만 남아 질문이 뜸한 고객사는 매번 처음 읽기(캐시 쓰기는 입력가의 1.25배) |
| 어휘 검색 (pg_trgm) 상위 k개 | Postgres 확장 하나(GIN·GiST 색인)로 외부 서비스 없이 검색, 질문과 비슷한 k개만 넣어 입력이 지식 크기를 덜 따라감 | 조사가 붙으면 3글자 조각이 달라져 유사도가 떨어짐(dev Postgres 16 실측 '환불 정책'과 '환불은 어떻게 하나요' 0.125, 기본 문턱 0.3), 겹치는 글자가 없는 바꿔 말한 질문은 0('돈 돌려받을 수 있나요'), Postgres가 먼저 있어야 함(메모리 저장소로 도는 E2E·verify는 같은 검색을 따로 흉내) |
| 임베딩 RAG (pgvector) 상위 k개 | 글자가 달라도 뜻이 가까운 질문을 찾음(벡터 유사도), 벡터를 Postgres 안에 다른 데이터와 함께 저장 | Anthropic은 임베딩 모델이 없어 외부 제공자(Voyage AI 등)의 키·호출이 하나 더, 콘솔에서 FAQ를 고칠 때마다 다시 임베딩, 청크 크기·k와 근사 색인(HNSW·IVFFlat)을 조정해야 함(근사 색인은 결과가 달라질 수 있음) |

### 출처를 어떻게 보증하는가

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| API 자체 인용: `search_result` 블록 + `citations` (선택) | `cited_text`를 API가 원문 블록에서 잘라 줘 원문에 없는 인용문이 없음, 위치가 필드로 옴(`search_result_index`·`start_block_index`·`end_block_index`), `cited_text`는 출력 토큰에 세지 않음 | 인용의 최소 단위가 text 블록이라 FAQ `blocks`를 나누는 방식이 곧 인용 크기, 한 요청의 `search_result`가 모두 같은 인용 설정이어야 함, 구조화 출력(JSON)과 함께 쓰면 400 |
| 프롬프트로 출처 번호 표기 | API 기능에 기대지 않아 모델·제공자를 바꿔도 같은 방식, 표기 모양(번호·위치)을 프롬프트로 정함 | 모델이 없는 번호나 원문에 없는 인용문을 쓸 수 있어 서버가 대조해야 함, 인용문을 쓰면 출력 토큰이 됨 |

## 스스로 답해볼 유도 질문

1. FAQ 20~30개 규모에서 "검색 실패 위험"과 "요청당 비용·지연" 중 무엇을 더 무겁게 봤는가? 그 판단은 지식이 몇 토큰쯤일 때 뒤집히는가?
2. API 자체 인용이 보증하는 것과 보증하지 않는 것은 무엇인가? (힌트: 인용문이 원문에 있다는 것 vs 그 원문이 답의 주장을 실제로 뒷받침하는지)
3. 프롬프트 캐싱의 기본 수명 5분은 희영 규모의 트래픽에서 주로 어디서 맞는가? 실제 적중률은 무엇으로 재는가?
4. 문서에 없는 질문에 "모른다 + 상담원 연결"로 답하게 하는 규칙은 이 결정과 어떻게 이어지는가?
5. 나중에 검색 단계를 앞에 붙인다면 무엇이 바뀌고 무엇이 그대로인가?

## 결과 확인 방법

- 데모 FAQ에 있는 질문: 답변에 인용이 붙고, 인용문이 해당 FAQ 원문과 일치한다.
- 문서에 없는 질문: 답을 지어내지 않고 모른다고 답하며 상담원 연결을 권한다 (W5 평가셋 핵심 케이스).
- 같은 대화 두 번째 턴 응답의 `usage`에서 `cache_read_input_tokens`가 0보다 크다 (캐시 적중).
- 데모 지식의 실제 토큰 수를 토큰 카운트 API로 재서 이 문서에 기록한다.
