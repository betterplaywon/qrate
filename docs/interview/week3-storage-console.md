# W3 면접 질문 뱅크 — Postgres · Prisma 마이그레이션 · 운영 콘솔 · 상담원 연결 접수

사용법은 [W1](week1-infra.md)과 같다: 코드를 보지 않고 답한다 → 답을 적어 Claude 세션에 첨부하고 **"채점해줘"** → 막힌 것은 코드를 읽고 다시 답한다 → 잘 답한 것 하나를 블로그로 옮긴다.

W3 결정은 ADR-0006(콘솔 인증·위치·핸드오프 범위·큐 정의)에 있다. ADR의 "스스로 답해볼 유도 질문"은 여기서 반복하지 않는다 — ADR에 답을 쓴 뒤 말로 재연습한다.

## Postgres · Prisma

1. Prisma 7은 드라이버 어댑터(`@prisma/adapter-pg`)가 필수이고 쿼리 컴파일러가 WASM이다. 이것이 런타임 이미지에 무엇을 넣지 않아도 되게 했나? 이전 세대(Rust 엔진 바이너리)와 비교해 설명하라.
2. 생성된 클라이언트(`src/generated`)를 git에 넣지 않고 `postinstall`과 빌드에서 다시 만든다. 이 선택이 CI·Docker·새 동료의 첫 설치에서 각각 무엇을 요구하는가? 넣는 쪽을 택했다면 무엇이 달라졌을까?
3. Prisma CLI는 `.env`를 읽지 않는다. 서버·CLI·테스트가 각각 환경변수를 어디서 어떻게 읽는지 세 줄로 말하라. 테스트가 `.env`에서 `QRATE_TEST_*`만 올리는 이유는?
4. `pnpm deploy --prod`가 Prisma CLI 트리(약 220MB)를 런타임 이미지에 담았다. 원인은 무엇이었고(선택적 peer), `pnpm.overrides`로는 왜 안 됐으며, `.pnpmfile.cjs`는 무엇을 바꾸나? lockfile의 `pnpmfileChecksum`은 왜 필요한가?
5. `onlyBuiltDependencies`에 `@prisma/engines`만 넣고 `prisma`는 넣지 않았다. 각 패키지의 설치 스크립트가 하는 일과, 허용하지 않았을 때 생기는 일(네트워크·시점)을 말하라.

## 마이그레이션

6. 두 번째 마이그레이션은 Prisma 초안을 그대로 못 쓰고 손으로 고쳤다. 무엇이 실패했고(필수 열 + 기존 행) 세 단계로 어떻게 풀었나? 빈 DB에서도 같은 결과가 나오는 이유는?
7. "마이그레이션을 시작한 뒤 개발 DB에 `db push`를 쓰지 않는다"는 규칙은 무엇을 지키나? 어기면 어떤 상태가 되고 어떻게 되돌리나?
8. 브랜치 안의 자잘한 마이그레이션을 머지 전 하나로 정리하기로 했다. 이미 다른 환경(동료 DB·스테이징)에 적용된 뒤라면 그 규칙은 어떻게 달라져야 하나?
9. `Message.seq`를 둔 이유를 "같은 트랜잭션의 질문·답"으로 설명하라. `createdAt`만으로 정렬하면 어떤 경우에 틀리고, 전역 시퀀스가 대화 안의 순서를 보장하는 이유는?
10. `KnowledgeItem`을 복합 키 `[tenantId, id]`로 둔 이유는? 전역 유일 id였다면 두 번째 테넌트를 시드할 때 무슨 일이 생기나?
11. 지식 조회는 DB `ORDER BY` 대신 JS에서 정렬한다. 콜레이션이 구두점을 어떻게 다루길래 그런가? 테스트는 어떤 id로 이것을 고정하나?
12. W1에 설계만 해 둔 `CreditLedger`·`Event`를 첫 마이그레이션에 그대로 포함했다. 포함한 이유와, W4에서 `@@unique([tenantId, idempotencyKey])`로 바꿀 때 마이그레이션이 하는 일은?

## 저장소 계약 · 테스트

13. 같은 계약 테스트를 메모리·Postgres 두 구현에 돌린다. 메모리가 숨기는 차이(FK, 트랜잭션 되돌리기, 프로세스 간 가시성) 중 어느 것을 DB 전용 케이스로 두었고, 왜 메모리에선 잴 수 없나?
14. `appendTurn`은 upsert → 테넌트 확인 → `createMany` → 핸드오프의 한 트랜잭션이다. 테넌트가 다를 때 던지면 무엇이 되돌아가고, 중간에 핸드오프 insert가 실패하면(enum 밖 값) 무엇이 남나? 테스트는 이것을 어떻게 재현했나?
15. 커서 페이지네이션의 커서는 `(createdAt, id)`이고 오프셋을 쓰지 않는다. 새 대화가 끼어들 때 오프셋이 틀리는 과정을 말하고, 커서가 불투명(base64url)이어야 하는 이유를 말하라. id tie-break가 콜레이션과 무관한 이유는?
16. Postgres 계약 테스트는 전용 DB(`qrate_test`)를 쓰고 변수가 없으면 건너뛴다. 개발 DB를 쓰지 않는 이유와, "건너뜀"이 CI에서 조용히 비어 버리는 것을 무엇이 막나?
17. 메모리 핸드오프 id가 무작위라 같은 밀리초의 두 건 정렬이 흔들렸다(5회 중 1회 실패). 왜 Postgres에선 괜찮았고(cuid), 메모리 id를 어떻게 바꿨나? "간헐 실패"를 처음 봤을 때 무엇부터 의심해야 하나?

## 콘솔 인증 · 세션

18. 로그인 실패는 테넌트가 없든 키가 틀리든 같은 401이다. 테넌트 키는 공개값인데도 왜 나누지 않았나? 로그인 시도를 IP당 10회/분으로 막는 것과 scrypt의 느림은 어떻게 역할을 나누나?
19. 세션 쿠키 `HttpOnly; SameSite=Strict; Path=/api/console`의 세 속성이 각각 막는 공격을 말하라. `Secure`를 https일 때만 붙이는 이유와, 로컬 http에서 붙였다면 무슨 일이 생기나?
20. `SameSite=Strict`가 있는데도 login·logout·PATCH에 Origin 검사를 또 둔다. 둘이 겹치는 부분과 겹치지 않는 부분은? GET에는 왜 두지 않았나(CORS 헤더가 없다는 사실과 연결해서)?
21. 세션 비밀 `QRATE_CONSOLE_SECRET`이 없으면 프로세스마다 무작위다. 서버가 둘이면 어떤 증상이 나고, 비밀을 바꾸는 것이 왜 "강제 로그아웃"과 같은가?
22. 직접 짠 HMAC 토큰을 jose(JWT)로 바꿨다. 기능은 같은데 무엇이 더 안전해졌나? 검증 때 `algorithms`를 고정하지 않으면 생기는 고전적 문제는?
23. 개발 서버의 Vite 프록시가 Origin 헤더를 서버 오리진으로 바꾼다. 이것이 "개발 편의로 보안 검사를 우회"인 이유와, 운영에서는 왜 같은 문제가 없는지를 오리진 개념으로 설명하라.

## 콘솔 API · 프런트

24. 콘솔 페이지와 API를 같은 서버·같은 오리진에 둔 결정이 CORS·쿠키·배포에 각각 무엇을 없앴나? 별도 오리진이었다면 로컬 데모에서 가장 먼저 막히는 것은?
25. 콘솔 문서의 CSP는 `default-src 'self'; frame-ancestors 'none'; base-uri 'none'`이다. 각 지시어가 막는 것과, 이 CSP 때문에 zod의 `new Function` 시험이 어떻게 드러났는지(`jitless`) 말하라. 해시 라우팅을 쓴 이유도 이 서빙 방식과 연결하라.
26. 서버 상태를 react-query로 옮기면서 화면에 데이터용 `useEffect`가 사라졌다. 세션을 "값이 null인 쿼리"로 두면 로그인·로그아웃·401이 각각 캐시를 어떻게 바꾸나? `useInfiniteQuery`가 커서를 어떻게 다루나?
27. ky 2는 오류 응답 본문을 미리 읽어 `error.data`에 둔다. `response.clone().json()`이 왜 실패했고, 증상이 "서버에 연결할 수 없어요"로 보인 이유(401 분기 실패)를 흐름으로 설명하라. 단위 테스트가 아니라 E2E에서만 드러난 이유는?
28. 로그인 폼의 zod 스키마를 서버와 공유한다(`@qrate/contracts/schemas`). 공유의 이점과 위험(스키마 변경이 두 곳을 동시에 바꾼다)을 말하고, 위젯 런처 번들에 zod가 들어가지 않게 한 방법(진입점 분리)을 설명하라.

## 미응답 큐 · 상담원 연결 접수

29. 큐에 "핸드오프 행만" 넣기로 했다. 거절·오류 턴과 인용 0건 턴을 뺀 이유를 각각 말하고, 그것들은 어디서 보게 될 것인가(W4 이벤트 로그)?
30. `Handoff.tenantId`를 비정규화했다. 대화의 `tenantId`와 어긋날 수 있나? 어긋나지 않게 하는 것은 제약인가 코드인가?
31. `POST /api/handoff`의 방어 순서(Origin → 요율 제한 → 본문 검증 → 테넌트 → 대화 소유 확인)를 말하고, 각 단계가 없을 때 가능한 남용을 하나씩 들어라. 브라우저 밖 호출은 무엇으로만 눌리나?
32. 방문자가 보낸 대화 id가 이 테넌트의 것이 아니면 새 대화를 만든다. 400으로 거절하지 않은 이유는? 그 결과 "질문 없는 대화"가 생기는데 콘솔과 목록 미리보기는 이것을 어떻게 다루나?
33. 운영자 실시간 답장(핸드오프 B)을 이번 주에 넣지 않았다. 큐·상태·연락처 중 B를 얹을 때 버려지는 것이 있나? B에 필요한 추가 조각(채널, 상태 기계, 부재 처리)을 열거하라.

## Docker · CI · 작업 방식

34. compose의 `migrate` 서비스는 빌드 스테이지 이미지로 `migrate deploy`와 `db seed`를 돌린 뒤 종료하고, 서버는 `service_completed_successfully` 뒤에 뜬다. 런타임 이미지에 CLI를 넣지 않은 이유와, 이 방식이 "운영 배포"에서는 어떻게 달라져야 하는지(마이그레이션을 누가, 언제) 말하라.
35. CI에 Postgres 서비스 컨테이너를 붙이고 `db:deploy`를 테스트 앞에 둔다. 스키마와 마이그레이션 파일이 어긋나면 어느 단계에서 어떻게 실패하나? E2E 서버는 왜 `QRATE_REPO=memory`로 고정했나?
36. 이번 주는 "결정 전에는 구현하지 않는다"(인증)와 "커밋 전 확인"(보안·아키텍처)을 지켰다. 그 규칙이 늦춘 것과 막은 것을 하나씩 들고, 같은 규칙을 팀에서 쓴다면 어디에 선을 그을지 말하라.
