# W2 면접 질문 뱅크 — 답변 엔진 · 지식 연결 · 테넌트 검증 · 위젯 분리

사용법은 [W1](week1-infra.md)과 같다: 코드를 보지 않고 답한다 → 답을 적어 Claude 세션에 첨부하고 **"채점해줘"** → 막힌 것은 코드를 읽고 다시 답한다 → 잘 답한 것 하나를 블로그로 옮긴다.

W2 결정은 ADR-0003(위젯 격리)·ADR-0004(지식 연결)에 있다. ADR의 "스스로 답해볼 유도 질문"은 여기서 반복하지 않는다 — ADR에 답을 쓴 뒤 말로 재연습한다.

## 답변 엔진 · 스트리밍 계약

1. `AnswerEngine` 인터페이스 뒤에 Claude 구현과 목업을 같은 모양으로 둔 이유를 한 문장으로? 그 덕에 CI·테스트·모델 교체에서 각각 무엇이 가능해졌나?
2. 첫 이벤트 **전** 실패는 HTTP 상태 코드(+`Retry-After`)로, 첫 이벤트 **뒤** 실패는 `event: error`로 보낸다. 왜 하나로 통일할 수 없나? (힌트: 헤더가 이미 나갔다)
3. 재시도 가능 여부(`retryable`)를 서버가 정하고 위젯은 따르기만 한다. 위젯이 상태 코드만 보고 스스로 판단하면 무엇이 문제인가? 429와 401로 설명해보라.
4. SSE 헤더를 보내기 전에 첫 이벤트를 "기다리는" 설계는 TTFT에 어떤 영향이 있나? 그래도 그렇게 한 이유는?
5. 클라이언트가 연결을 끊으면 모델 호출을 즉시 중단한다. 비용 관점에서 왜 중요하고, 서버는 어느 이벤트로 끊김을 알아채나? (W1 `docs/reviews.md` 2번 항목과 연결)
6. 서버 측 폴백을 켰다. "요청한 모델"과 "실제로 답한 모델"을 따로 기록하는 이유는? 둘이 다른 응답을 W5 평가셋에서는 어떻게 다뤄야 하나?

## 모델 선택

7. 기본 모델을 Sonnet 5.5 + 사고 끔으로 정한 두 근거는? 어떤 신호가 보이면 이 결정을 되돌릴 것인가?
8. 실측 3회(지식 없이 TTFT 1,180ms → FAQ 26개 주입 1,418ms → 같은 대화 2턴째 캐시 읽기 1,058ms)를 면접에서 어떻게 말할 것인가? "경향"과 "수치"를 구분해서 답하라.

## 지식 연결

9. FAQ 26개(접두사 약 7,400토큰)를 매 요청에 전량 넣는다. 캐시가 맞을 때와 안 맞을 때의 입력 비용 차이를 어림으로 말하고, 캐시 수명 5분이 이 제품의 대화 간격과 어떻게 맞물리는지 설명하라.
10. `cache_control` 지점이 둘(시스템 지시, 마지막 지식 블록)이다. 지식 블록을 시스템 지시가 아니라 **첫 user 턴**에 두는 이유는? 턴이 쌓여도 접두사가 유지되는가?
11. 지식 저장소는 항목을 **id 오름차순으로 고정**해 돌려준다. 순서가 요청마다 달라지면 어떤 일이 생기나?
12. `search_result` 블록 + `citations`가 보증하는 것과 보증하지 않는 것은? "원문에 있는 문장"과 "주장을 실제로 뒷받침하는 문장"의 차이로 답하라.
13. "자료에 없는 내용은 모른다고 답하고 상담원 연결을 안내한다"는 지시가 시스템 프롬프트에 있다. 지켜지는지 **무엇으로 측정**할 것인가(W5)? 시드 FAQ에 일부러 비워 둔 주제가 있는 이유는?

## 대화 저장

14. W2에 Postgres를 붙이지 않고 저장소 인터페이스 + 메모리 구현으로 끝낸 이유는? 그 대신 무엇을 약속했나? (계약 테스트, W3 첫날 마이그레이션)
15. `X-Conversation-Id`로 대화를 이어 가고 최근 10개 메시지만 history로 넣는다. 상한이 지키는 것과 잃는 것은? 다른 테넌트의 대화 id가 오면 어떻게 되나?
16. 실패한 턴의 질문이 대화에 남아 재시도 때 중복되던 문제를 "턴이 끝난 뒤 질문·답변을 함께 저장"으로 고쳤다. "먼저 저장하고 실패하면 지우기"와 비교해 무엇이 유리한가? W3 Postgres에서 두 insert는 어떻게 다룰 것인가?

## 테넌트 검증

17. 대화 API 앞의 Origin 검사는 "헤더 없음은 통과, 자기 오리진만 통과, 다른 오리진과 `null`은 403"이다. 헤더 없음을 통과시키는 이유는? 이 검사가 **막지 못하는** 호출은 무엇이고, 그것은 언제 어디서 막나?
18. W1의 CORS `*`를 제거할 수 있었던 구조적 이유는? CORS 헤더가 없을 때 다른 사이트의 스크립트가 `/api/chat`에 JSON을 보내면 브라우저에서 정확히 무슨 일이 일어나나? (힌트: 프리플라이트)
19. `Origin: null`은 어떤 상황에서 오나? 데모를 `file://`로 열면 안 되는 이유와 같은 이야기인가?
20. `frame-ancestors`(CSP)와 `X-Frame-Options`의 차이는? 둘을 같이 보내면 브라우저는 어느 쪽을 따르나?
21. `allowedOrigins`를 **시드 로드 단계**에서 정규형(`scheme://host[:port]`)만 받는 이유는? 경로·끝 슬래시·와일드카드(`https://*.example.com`)가 섞여 들어가면 CSP 헤더에 어떤 일이 생기나?

## 위젯 격리

22. 런처는 Shadow DOM, 대화창은 서버 오리진 iframe인 하이브리드를 골랐다. 런처까지 iframe으로 넣지 않은 이유와 대화창까지 Shadow DOM으로 두지 않은 이유를 각각 한 문장으로.
23. 대화창은 받는 postMessage를 세 겹(보낸 문서의 `origin`, `source === window.parent`, 메시지 형식)으로 확인한다. 각 겹이 막는 공격 또는 실수는? 보낼 때 `targetOrigin`을 `*`로 두면 무엇이 새나?
24. iframe은 자기를 넣은 부모 페이지의 오리진을 스스로 알 수 없다. 그래서 런처가 `o=<사이트 오리진>`을 쿼리로 보내고 서버가 `allowedOrigins`와 대조한다. 런처가 거짓 `o`를 보내면 어떻게 되나 — 어느 층이 막나?
25. `/frame` 문서의 CSP가 `default-src 'self'`라 인라인 `<script>`·`<style>`이 막힌다. 그래서 대화창 자산을 같은 오리진의 정적 파일로 서빙한다. nonce 방식과 비교한 트레이드오프는?
26. 대화창 자산 파일 이름에 해시가 없고 `max-age=0` + ETag 재검증을 쓴다. 이유는? 해시 파일명으로 바꾸면 무엇이 좋아지고 무엇이 복잡해지나?
27. 스니펫의 `data-tenant`를 필수로 만들었다(W1의 `demo` 기본값 삭제). 기본값이 있으면 무엇이 위험한가?
