# W6 면접 질문 뱅크 — 부하 측정 · 병목 찾기 · 시뮬레이션의 한계

사용법은 [W1](week1-infra.md)과 같다: 코드를 보지 않고 답한다 → 답을 적어 Claude 세션에 첨부하고 **"채점해줘"** → 막힌 것은 코드를 읽고 다시 답한다 → 잘 답한 것 하나를 블로그로 옮긴다.

W6 결과는 [docs/load/w6](../load/w6/README.md), 측정 장치는 [apps/server/load](../../apps/server/load/README.md)에 있다. 크레딧 원장의 트레이드오프는 [ADR-0007](../adr/0007-credits-and-payment-idempotency.md)에 있다.

---

## 무엇을 재나

1. 운영 서버를 그대로 k6로 치면 무엇을 재게 되나? 요율 제한을 환경변수로 풀지 않고 측정 서버에서만 `createApp` 옵션으로 올린 이유는? 그 대가로 측정에서 빠진 것은 무엇인가?
2. 목업 엔진으로 잰 "대화 첫 바이트"가 서버 몫인 이유를 SSE 헤더를 보내는 시점과 연결해 설명하라. 방문자가 실제로 느끼는 첫 글자 시간은 이 값과 무엇을 더해 추정하나?
3. 방문자 쪽(k6)의 첫 바이트와 서버가 DB에 적은 TTFT를 둘 다 봤다. 둘이 크게 다르면 무엇을 의심하나?
4. 이 측정은 "동시 방문자 N명"(닫힌 모델)으로 부하를 만든다. 서버가 느려지면 닫힌 모델의 부하는 어떻게 변하나? 도착률로 부하를 주는 열린 모델이었다면 지연 숫자는 어떻게 달라졌을까?
5. 방문자를 한꺼번에 넣지 않고 램프로 늘리고, 지표는 유지 구간에 시작한 요청만 셌다. 그러지 않으면 어떤 숫자가 섞이나?
6. 주석 검토가 시나리오와 위젯의 차이 둘(대화창 정적 파일, 첫 질문 사건의 순서)을 짚어 처음부터 다시 쟀다. 정적 파일이 빠진 시나리오는 어떤 숫자를 좋게 보이게 했나? 고친 뒤 무엇이 얼마나 달라졌나?

## 병목 찾기

7. 방문자가 늘어 p95가 튄 원인이 Node 이벤트 루프라고 말할 근거를 대라. 기기 전체 CPU에 여유가 있는데도 느려지는 이유는?
8. 같은 조건의 측정이 회차마다 크게 달랐다. 이벤트 루프 사용률이 높을 때 몇 초짜리 멈춤 하나가 p95를 어떻게 바꾸는지 대기열로 설명하라.
9. 서버·Postgres·k6가 한 기기에서 돈다. 부하를 만드는 k6 자신이 측정을 망치지 않았다는 것은 무엇으로 확인했나?
10. CPU 프로파일에서 소켓 쓰기(30%) 다음으로 큰 몫이 DB 접근 계층(Prisma, 27%)이었다. 한 턴에 어떤 쿼리가 나가나? 지식 목록을 테넌트별로 캐시하면 무엇을 새로 지켜야 하나?
11. 이벤트 루프 지연과 이벤트 루프 사용률(ELU)은 무엇이 다른가? `monitorEventLoopDelay`가 준 값에서 측정 해상도(10ms)를 빼야 밀린 시간이 되는 이유는?

## 원장과 잔액

12. 잔액을 원장 합계로 구하는 설계(ADR-0007)의 장점은 무엇이고, 이번 측정에서 드러난 대가는 무엇인가? 잔액 열이나 스냅샷을 두면 동시에 들어온 차감에서 무엇을 지켜야 하나?
13. 사다리의 단계마다 새 테넌트를 썼다. 한 테넌트로 방문자 수를 올렸다면 어떤 잘못된 결론을 냈을까?

## 시뮬레이션을 말하는 법

14. 이 결과를 "시뮬레이션 기준"이라고 적은 이유를 대라. 면접에서 "서버가 몇 명까지 버티나요?"라고 물으면 어떻게 답하겠나?
15. 목업 엔진은 글자마다 SSE 한 줄을 쓴다. 실제 모델 스트림이었다면 서버 CPU는 어느 쪽으로 달라질까? 근거는?
16. 서버를 프로세스 여럿으로 늘리면 지금 프로세스 메모리에 있는 무엇이 깨지나(요율 제한 카운터, 콘솔 세션 비밀, 모의 결제 서명 비밀)?
