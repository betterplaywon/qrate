# W5 면접 질문 뱅크 — 응답 품질 평가셋 · 답 기준 · 심판 검증

사용법은 [W1](week1-infra.md)과 같다: 코드를 보지 않고 답한다 → 답을 적어 Claude 세션에 첨부하고 **"채점해줘"** → 막힌 것은 코드를 읽고 다시 답한다 → 잘 답한 것 하나를 블로그로 옮긴다.

W5 결과와 실패 사례는 [docs/eval/w5](../eval/w5/README.md), 실행 장치는 [apps/server/eval](../../apps/server/eval/README.md)에 있다.

## 시험지와 채점

1. 30문항을 넘겨야 함 9, 넘기면 안 됨 18, 채점 안 함 3으로 나눴다. 넘김을 "넘겨야 함"으로만 쟀다면 어떤 모델이 높은 점수를 받을 수 있었나?
2. 한 문항은 2회 모두 충족해야 충족이다. 회차 충족(Sonnet 52/60)과 문항 충족(25/30) 중 무엇이 제품 품질에 가까운가? 회차를 늘려도 줄지 않는 불확실성은 무엇인가?
3. 기계 검사 9종과 LLM 심판은 무엇을 기준으로 나눴나? "지어냄"을 기계 검사로 잡을 수 없는 이유는?
4. 심판(Opus 5.5)에게 같은 모델의 두 회차 답을 한 번에 보냈다. 비용 말고 무엇을 얻고 무엇을 잃나?
5. 일부러 나쁜 답 3종(빈 답, "모르겠습니다", 확신에 찬 틀린 답)으로 심판을 점검했다. 이 점검을 통과해도 심판을 믿을 수 없는 경우는 어떤 것인가?

## 사람 채점과 답 기준

6. 1회차 "알맞음" 일치율 73%는 대부분 심판의 오류가 아니라 기준의 차이였다. 일치율이 낮을 때 심판 지시부터 고치면 무엇이 잘못될 수 있나?
7. 답 기준 C(고객사가 자료에 "지원하지 않는다"고 적은 기능만 단정)와 B(자료에 없으면 없다)를 비교하라. B는 고객사에 어떤 위험을 주나? C는 고객사에 어떤 책임을 지우나?
8. 2회차 "알맞음" 27/30은 관문 문구("90%"와 "90% 넘게")의 경계였다. 그대로 진행한 근거 두 가지는 무엇인가? 같은 상황을 다음에는 어떻게 막겠나?

## 고친 결함

9. m02에서 넘긴 다음 턴에 앞 질문을 다시 넘겼다. 대화 기록을 모델에 다시 보낼 때 무엇이 빠졌기에 생겼나? 기록에 도구 호출을 재현하지 않고 넘김 안내 문장으로 고친 이유는?
10. h01에서 모델이 넘김 도구 호출을 본문 글자로 썼다. 스트리밍 중에 이런 태그를 거르려면 조각 경계에서 무엇이 어렵나? 태그를 버리기만 하지 않고 넘김 신호를 살린 이유는?
11. 되풀이 거르기 필터는 반복이 아닌 글을 몇 글자 늦게 내보낸다. 왜 그런가? 실제 답 116개를 필터에 다시 흘려 무엇을 확인했나? 말을 바꾼 되풀이(k05)는 왜 같은 방식으로 거를 수 없나?
12. 지시(프롬프트)로 고칠 결함과 엔진 코드로 막을 결함은 무엇을 기준으로 나눴나? 같은 문장 되풀이는 왜 지시로 줄지 않았나?

## 비용과 결정

13. 비용 관문은 호출 전에 장부에 적고, 진행 중인 호출의 최대 비용까지 더해서 새 호출을 허락한다. 실제로 쓴 돈이 상한보다 한참 아래인데도 멈출 수 있는 이유는? 그래도 이 방식을 고른 이유는?
14. Haiku 5.5는 답 비용이 1/14이고 TTFT p50이 0.4초 빨랐지만, 문항 충족은 8/30이었다. 기본 모델을 Sonnet 5.5로 둔 판단을 비용·속도·품질로 설명하라. Haiku로 바꾸려면 무엇을 먼저 재야 하나?
15. 판정 한 건($0.0125)이 답 한 건(Sonnet $0.0031)보다 비쌌다. 시험지를 키울 때 채점 비용을 줄이는 방법은 무엇이 있나?
