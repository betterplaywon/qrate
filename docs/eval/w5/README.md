# W5 응답 품질 평가 결과

위젯 답의 품질을 30문항 시험지로 재고, 기본 모델 후보인 Sonnet 5.5와 Haiku 5.5를 비교했다. 실행일은 2026-11-11이고, 모든 수치는 이 폴더의 기록에서 센 실측값이다.

**요약.**
- 시험지 v2에서 Sonnet 5.5는 30문항 중 25문항, Haiku 5.5는 8문항이 두 번 모두 기준을 채웠다. 기본 모델은 Sonnet 5.5로 둔다.
- 작성자가 직접 채점한 30개와 심판(Opus 5.5)의 판정은 지어냄 30/30, 알맞음 27/30이 같았다.
- 1회차 사람 채점에서 "좋은 답"의 기준이 바뀌었다(답 기준 C). 그래서 프롬프트와 시험지를 고친 뒤 2회차로 다시 쟀다.
- 실제 모델 호출은 330건, 비용은 $1.79였다.

## 무엇을 쟀나

- **시험지.** `apps/server/eval/cases.json` v2(작성자 승인), 30문항이다. 가상 데모 고객사(마루인보이스, FAQ 27개)의 FAQ 원문으로 정답지를 만들었다. 넘김 기대는 넘겨야 함 9, 넘기면 안 됨 18, 채점 안 함 3이다.
  - 묶음: 자료 질문 7, 두 항목·조건 2, 지원하지 않는 기능 5, 비워 둔 주제 4, 사업 질문 3, 사람 처리 2, 무관한 질문 1, 인사 1, 지시 바꾸기 2, 영어 1, 이어지는 대화 2.
- **모델.** Sonnet 5.5와 Haiku 5.5를 운영 설정(사고 끔, `max_tokens` 1024)으로 문항마다 2번씩 돌렸다. 서버 측 폴백으로 다른 모델이 답하면 오류로 빼도록 했는데, 그런 답은 0건이었다.
- **실행.** 운영과 같은 대화 유스케이스(`createChatService`)를 메모리 저장소로 직접 불렀다. HTTP, 요율 제한, Origin 검사는 거치지 않는다. 첫 글자 시간(TTFT)은 유스케이스 호출부터 쟀다.
- **채점.**
  - 기계 검사 9종: 정상 종료, 넘김 기대, 넘길 때 안내 문장, 인용, 꼭 있어야 할 낱말, 질문 언어로 답함, 내부 표현("자료"), 본문 도구 태그, 15자 이상 문장의 되풀이.
  - 심판(Opus 5.5, effort low): 자료가 뒷받침하지 않는 사실을 단정했는지("지어냄"), 기대와 말투 기준대로 답했는지("알맞음"). 같은 모델의 두 답을 섞어 한 번에 채점했다.
  - 한 회차는 기계 검사를 모두 통과하고 심판이 "지어냄 없음·알맞음"으로 볼 때 충족이다. 한 문항은 2회 모두 충족해야 충족이다.
- **심판 검증.** 작성자가 Sonnet 1회차 답 30개를 심판 판정을 보지 않고 채점해 일치율을 쟀다.

| --- | --- | --- |

| 넘김 놓침(넘겨야 하는 회차) | 0/18 | 0/18 |
| 넘기면 안 되는데 넘김 | 0/36 | 2/36 |
| 지어냄(심판) | 0/60 | 2/60 |
| 내부 표현("자료") | 0/60 | 16/60 |

| 넘길 때 안내 문장이 빔 | 0/18 | 0/21 |
| 인용 빠짐 | 2/36 | 0/36 |
| TTFT p50 / p95 (n=60) | 1,123 / 1,544 ms | 700 / 1,048 ms |

| 답 60개 비용 | $0.1875 | $0.0130 |

p50·p95는 콘솔 지표와 같은 nearest-rank 정의다. 프롬프트 접두사는 도구 정의, 시스템 지시, FAQ 27개를 합친 것이다. 2번째 호출부터는 전부 캐시에서 읽혔다. 1회차는 FAQ 26개와 이전 시스템 지시라 접두사가 8,146 토큰이었다. 자세한 표는 [v2/report.md](v2/report.md)에 있다.

**결론.** Haiku는 답 비용이 1/14이고 TTFT p50이 0.4초 빠르다. 하지만 30문항 중 22문항에서 기준을 채우지 못했다. 그래서 기본 모델은 Sonnet 5.5로 둔다(`QRATE_MODEL` 기본값 그대로). Haiku를 쓰려면 지시 따르기를 따로 다듬어야 한다.

## 1회차에서 2회차로

**1회차(시험지 v1).** Sonnet 5.5만 쟀고, 30문항 중 26문항이 기준을 채웠다(회차 54/60). 그런데 작성자 채점과 심판의 일치율이 지어냄 90%, 알맞음 73%로 관문에 못 미쳤다. 갈린 판정 11개 중 10개는 심판의 오류가 아니라 기준의 차이였다.
- 시험지와 시스템 지시는 "자료에 없으면 모른다고 말하고 상담원에게 넘긴다"를 정답으로 삼았다.
- 작성자는 "없으면 없다, 있으면 있다 확실하게"를 원했다. 모바일 앱, 외화, API, 국세청 전송, 카카오톡처럼 없는 기능은 없다고 단정해야 한다고 봤다.

**답 기준 C(작성자 결정).** 지원하지 않는 기능은 고객사가 자료에 적은 것만 "없다"고 단정한다. 자료에 언급이 없는 것은 있다·없다 단정하지 않고, 상담원이 이어서 안내한다고 말한 뒤 넘긴다. 자료에 없으면 무조건 없다고 하는 방식(B)은 자료에서 빠진 실제 기능을 부정할 수 있어 고르지 않았다.

**바꾼 것(PR #45).**
- 시스템 지시: 결론 먼저, 내부 표현·"참고로" 덧붙임·되풀이 금지, 방문자 언어로만, 무관한 질문은 넘기지 않음, 이미 넘긴 질문은 다시 넘기지 않음.
- 엔진: 본문에 글자로 쓴 도구 호출을 방문자에게 보내지 않고 신호를 살린다. 바로 앞 문장의 끝을 되풀이한 문장을 버린다.
- 데모 자료: "지원하지 않는 기능" 항목(휴대폰 앱, 외화 청구와 환율, 공개 API와 웹훅, 국세청 전자세금계산서 전송, 카카오톡 알림)을 더했다.
- 시험지 v2, 심판 기준, 기계 검사 4종을 더했다.

중간에 짧은 시험을 2번 했다(14문항 × 두 모델 × 1회, 각 28건). 1번째에서 되풀이, 덧붙임, "자료" 변형 표현, Haiku의 영어 혼잣말이 나와 지시와 검사를 고쳤다. 2번째에서도 같은 문장 되풀이가 줄지 않아 엔진 필터로 막았다.

**같은 결함이 어떻게 바뀌었나(Sonnet 답 60개 기준).** 1회차와 2회차는 채점 기준이 달라 충족 수를 바로 견줄 수 없다. 대신 같은 규칙으로 센 결함 수를 견준다.

| 결함 | 1회차 | 2회차 |
| --- | --- | --- |
| 내부 표현("안내 자료에 없습니다" 등) | 33 | 0 |
| "참고로"로 시작하는 덧붙임 | 16 | 1 |
| 같은 문장 되풀이 | 1 | 0 |
| 본문에 도구 태그 노출 | 1 | 0 |
| 넘긴 다음 턴에 앞 질문을 다시 넘김(m02, 2회 중) | 2 | 0 |
| 출력 토큰 p50 | 223 | 168 |

## 심판을 믿을 수 있나

- **2회차 일치율.** 지어냄 30/30(100%), 알맞음 27/30(90.0%). 결과는 [v2/agreement.md](v2/agreement.md)에 있다.
  - 갈린 셋(k05, n02, n03)은 모두 사람이 "알맞음", 심판이 "알맞지 않음"이었다. 심판은 승인된 기준을 그대로 적용했다. 되풀이 금지(k05, n03)와, n02 기대 칸의 "문서 양식 이야기는 묻지 않은 덧붙임"이다.
  - 관문은 결정할 때 "90%"로 정했는데, 평가 README에는 "90% 넘게"라고 적어 문구가 엇갈렸다. 27/30은 정확히 90%라 엄격히 읽으면 경계다. 갈린 방향이 한쪽(심판이 더 엄격)이고 두 모델에 같은 심판을 쓰므로 비교에는 영향이 없다고 보고 진행했다.
- **1회차 일치율.** 지어냄 27/30, 알맞음 22/30이었다([v1/agreement.md](v1/agreement.md)). 원인은 위의 기준 차이였다.
- **심판 점검.** 일부러 나쁜 답 3종(빈 답, "모르겠습니다", 확신에 찬 틀린 답)을 사례 2개에 넣었다. 두 회차 모두 6개를 전부 실패로 봤다([v2/judge-check.jsonl](v2/judge-check.jsonl)).

### 2회차 Haiku: 22문항

- 심판이 "알맞지 않음"으로 본 40회차 중 20회차의 근거가 되풀이였다(그중 4개는 심판이 근거를 영어로 썼다). "스타터 플랜은 월 9,900원입니다. 스타터 플랜은 월 9,900원이며…"처럼 결론 문장 뒤에 같은 내용의 자료 문장을 다시 쓴다. 자료 질문 k01~k06이 대부분 여기서 떨어졌다.
- "자료"라는 내부 표현을 16회차에 썼다("제공된 자료에는 …이 없습니다" 등).
- 한국어 질문 3회차에 영어로 답하거나 영어 혼잣말을 붙였다(b01, b03, h02).
- n03에서 지원하지 않는다고 답한 뒤 상담원에게 넘겼다(2/2).
- 지어냄은 2회차였다. n01은 "PC 웹에서 작성한 뒤 발송"이라는 자료에 없는 방법을 말했다. i01은 자료에 언급이 없는 쿠폰을 "발급하지 않는다"고 단정했다.
